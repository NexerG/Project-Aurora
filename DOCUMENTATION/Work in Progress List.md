# PHASE A — Periodic MVP + engine hygiene (now → ~Jul 2026)
- [x] **shutdown is a sequence, mirroring bootstrap (2026-08-21)** — `Shutdown.cs` + `Shutdown.xml` are a structural copy of `Bootstrapper`/`Bootstrap.xml`: named phases holding ordered steps, each step naming an `[A_XSDActionDependency(name, "Shutdown")]` static, resolved by reflection and invoked in declared order. Every step returns `bool` and a `false` halts its phase. **Two phases**, because they answer different questions: `Request` may refuse and owns anything that asks the user; `Commit` is past the point of no return and runs against a still-live tree. A step that must prompt returns `false` and the prompt's callbacks call `Shutdown.Resume()` to re-run the sequence — one question per attempt, cancelling just never resumes. Same pass: all **21** bootstrap steps converted to `bool` with `Bootstrapper.RunPhase` halting on failure; `WindowActions.CloseWhenNamed` moved to `NoteActions` and generalised across every window, with per-window close reusing it through `SettleWindow`; `SettingsRegistry.SaveAll` — which had **zero callers**, so settings had never been written back — is now the second `Commit` step. **Not GUI-verified**: builds clean and boots, and the three action names resolve, but no exit path has been walked. See `ClaudeMemory/Decisions/shutdown-sequence.md`
