- [x] **UI Engine landing 1 — the new stack draws (2026-09-06)** — attempt 3 at the UI rework, and the approach changed: a **parallel build** in a new namespace `ArctisAurora.Core.UI`, not the in-place migration of `UIControls` that `ui-data-control-split` planned, so the old stack stays whole and runnable until it is deleted wholesale at landing 6. **Two things are now called a control and swapping them inverts every sentence**: `Control` is the CPU tree node, `VulkanControl` is one GPU quad (a struct, tagged `MTSDFControl`/`PanelControl`/`ImageControl`), and one `Control` owns 0..N of them — a panel owns one, a text run owns one per glyph, which is what removes the 56.7k-glyph-object ceiling. Data splits three ways: `ArrangeData` 140 B CPU-only, `ControlGeometry` 96 B and `VulkanControl` 92 B on the GPU as **two independently-dirtied buffers**, because today's 136 B `ControlData` mixes arrange output with paint and re-uploads 4.25× more than changed on every resize. Landed: both pools in `Pools.pools.xml`, `UIEngine` + its bootstrap step, `Control : Entity`, `UIEngineModule` as a second module on every window at `compositorOrder = 10` with a transparent clear, a new shader pair mirrored byte-identical to all three host trees, and `ERendererTypes.UIEngine` with its `AuroraCamera` case. Same pass: **`edge` and `outline` merged to one `edge` pair** in design pixels whose meaning the kind selects — they stroked two different distance fields and *neither had a single consumer anywhere in the repo* — and `CompositorModule` was fixed to specialize `MODULE_COUNT` into `stages[1]` rather than a local already copied into the `stackalloc`, which meant the constant had **never** been applied and a second module rendered into an image the compositor never sampled, with no validation error. Two traps recorded: the ortho box only accepts world z ≤ −0.01, so a control at z = 0 is near-plane clipped and draws nothing (a window root sits at −10); and `Renderer.PrimaryRendererType` is `modules[0].rendererType`, so `ui` must stay at index 0. **GUI-verified**: a rounded blue panel with a white edge renders at (80,80,320,180) through both new pools, the new module and the new shaders, screenshotted with the old UI drawing underneath it unchanged; row sizes read back from `Unsafe.SizeOf` at boot; all three hosts build clean. - [x] **UI Engine landing 2 — tree and layout (2026-09-06)** — the new stack now measures, arranges and takes a per-window slice of the draw pool. `Control.Measure`/`Arrange` are the outgoing stack's two-pass shape moved onto `ArrangeData`: `WriteArranged` bakes the matrix into `ControlGeometry` one depth step nearer the camera than the parent and settles the clip by inheriting or intersecting it, `ArrangeFlags` packs clip/hidden/measure-dirty/arrange-dirty into the flags byte, and the alignment and dock bytes get enums — **untagged**, because the old stack owns those `[A_XSDType]` names and `AnyXMLType.FindType` resolves by name alone. - [x] **UI Engine landing 3 — input (2026-09-06)** — the new stack answers the pointer. `UIEngine.Poll` runs at the top of `Engine.HandleUI`, ahead of that method's own guards so the pointer *leaving* a window still clears a hover — scoped to the polling window's own tree, since every window polls and the contexts are global. `HitTest` is a `subtreeBounds` early-out, then the node's own `clip` and `arranged`; `Dispatch` is one walk from the hit control up through its parents until a handler returns `true`, and **every phase goes through it, enter and exit included**. `PointerEvent` carries the control actually under the pointer, so an ancestor handling a bubbled event knows what was hit. **Hover is one control, not a chain** — hovering a glyph does not make its document, its panel and the window root "hovered"; ancestors hear about it only because the event bubbles, which is exactly what lights a button when the pointer is over its label. Three forks the user settled: contexts registered as `NextHovering` / `NextActiveControl` / `NextPressTarget` and renamed at L6, because `A_ActiveContext` registers by name into one dictionary and last-wins — reusing `ActiveControl` would take the old stack's slot and quietly stop `Thorium.contexts.xml`'s `ActiveTabViewer` deriving; delegate handlers built now alongside the virtuals, one `Func<PointerEvent,bool>` per phase, **last registration wins** because a multicast `Func` returns only the last answer and OR-ing the invocation list allocates on every `Move`; and the hit-test walks children **last to first**. That last one is a fix, not a port: depth testing is off on both UI pipelines, so what is on top is purely what was drawn last, and the old `FindDeepestValid` iterates forward and returns the first subtree containing the point — it never compares candidates, so an overlapping pair hands the click to the sibling drawn *underneath*. `WindowControl.AddOverlay` is the case that would bite and it only escapes because `SolveHover` re-roots at an open menu first. The transformed-quad test is gone with it: nothing rotates, so `arranged.Contains` is exact and a degenerate rect is simply false instead of vacuously true. **GUI-verified**: hovering `leaf` lights `leaf` and bubbles through `inner` (a plain `Control`, no handler, visibly unchanged) to `card`, which consumes it; leaving returns both to resting; two overlapping siblings hand the hit to the one drawn on top, and to the exposed arm of the one underneath; a press recolours the pressed control. **Not exercised**: double-tap, right button, and the pointer leaving the window. See `ClaudeMemory/Decisions/ui-engine-stack.md`, `ClaudeMemory/Context/ui-engine-plan.md` and `Engine/Systems/UI-ENGINE.md`
- [x] **UI Engine landing 4 — text and caret (2026-09-06)** — a paragraph is now **one control and one draw row per character**, which is the change that removes the 56.7k-glyph-object ceiling. `Control.controlHandle` became `Control.rows`, a `DataHandle[]` whose first entry is the element's own quad; `AllocateRow`/`TrimRows` grow and shrink the tail, `Entity` grew `FreeIn` because `_extraHandles` previously only ever emptied at destroy, and the DFS walk that keys both pools now emits every row — with a de-duplicating guard, since the detached-subtree sweep meets a run once per row it owns. `TextRunControl` holds the string plus a `List<StyleSpan>` that **tiles it in order with the last span absorbing the remainder**, so appending text needs no span edit and neither overlaps nor holes are expressible; each span becomes one input run for `TextMeasurer`, which gained `charStart`/`charCount` so N spans **slice one string** instead of cutting N substrings on every keystroke — the old four-argument `Run` still spans the whole string, so no outgoing call site moved. Rejected alternative: one style per run, which sounds smaller until you notice a plain `Control` throws on a second child and containers do not arrive until L6 — without spans a paragraph could not hold a bold word at all. Glyphs land at `rows[1 + charIndex]`, so character→row never depends on how the lines broke. The run keeps its own transparent `rows[0]` rather than owning none, because `WriteArranged`, `depth`, `ClipRect` and `SetGradientSpace` all write through it and four base members would otherwise have to learn about a rowless control to save one quad per paragraph. Shader: the vert passes the row's atlas cell, texture index and kind; the frag takes **set 2** as the texture table and branches on `MTSDFControl`, with both branches filling one `dist`/`aa` pair so the merged `edge` band is one piece of code for a glyph silhouette and a rounded box alike. `UIEngineModule` grew the sampler set, the descriptor-indexing features and a `WriteTextureTable` keyed on `TextureAsset.TableVersion`. The caret belongs to the **document**, so the scaffolding grew a `ProbeDocumentControl` to be one — a run owning its own caret gets the count wrong the moment a document holds two runs. **Departure mid-build**: `CaretControl` collides with the outgoing one at `AssetRegistries.RegisterSerializableTypes`, which hashes the *simple* name while `[@Serializable]` is inherited — renamed `NextCaretControl`, the same workaround as `VulkanControlData` and the `Next` contexts, and the third time this family has bitten. **Deferred, each waiting on something specific**: `SelectionControl` (needs drag ported), `DocumentEditorControl.CaretAtPoint` (needs blocks), the per-character XML shape (the new stack parses no XML at all). **GUI-verified**: a three-span paragraph wraps at 360 into three lines with the amber bold span crossing a line boundary carrying the right characters; four probed clicks put the caret at line 1 offset 0 (x 24), mid line 1 (clicked 217 → caret 219), line 2's start past the first character's midpoint (x 36) and line 3's end (x 334), line tops exactly 24 px apart; the caret blinks; no resequence warning and no DEBUG subtree-cache mismatch through boot, layout and four clicks; no validation error beyond the pre-existing `DemoteToHelperInvocation` pair. **Not exercised**: editing text after the first measure, two runs in one document, a family with a real bold face, and `edge` on a glyph. - [x] **UI Engine landing 5 — images, icons, masks and gradients (2026-09-06)** — the third quad kind and the gradient table arrive, and **no struct changed**: `uvs`, `textureIndex` and `gradientIndex` were already in `VulkanControl` and `gradientRect` already in `ControlGeometry`, all written by nothing since landing 1, so the row sizes are still 140 / 96 / 92 and neither `scalar` stride moved. `Control` grew `kind`, `sampler`, `gradient` and `SetUVRect`, the last of which is the one place that knows the quad mesh's vertex order is `(u1,v1),(u0,v0),(u0,v1),(u1,v0)` and not a min/max pair. **One sampler slot whose meaning `kind` selects** — the distance field on a glyph or icon, a coverage mask on a panel, the colour source on an image — which is the same answer the merged `edge` pair took, for the same reason: three slots each with one consumer is worse than one with three readings. The price was taken knowingly and is that **an image cannot also carry a mask**; the fix is a second index plus a second UV set, which grows the 92 B row that a paragraph holds several hundred of. "No texture" is `uint.MaxValue`, **not** a reserved slot 0 — gradients could reserve slot 0 because one loader builds that table, but the texture table fills in asset-load order and slot 0 is `defaultMask.png`, a real texture the outgoing stack still resolves `maskAsset = null` to, so reserving it would have meant a null texture, a change to `TextureAsset` and a behaviour change in the stack being deleted. Named `sampler` by the user over `texture` and `maskAsset`, both of which name one of the three readings; `SamplerAsset` and `Silk.NET.Vulkan.Sampler` already exist in the same render path, which is a readability collision and not a C# one. **The mask multiplies last, after the edge band**, so a masked control is one silhouette and its border follows the mask instead of floating around it as the rounded rectangle it would otherwise be. The gradient table returns at **set 1 binding 3** — the numbering the old shader already uses, so nothing renumbered — with `sampleGradient` copied verbatim from `UIRasterizer/UI.frag`, whose 184-byte layout is already proven against C# `GpuGradient`; the buffer is a **static** on `UIEngineModule`, built once in `PrepareObjects` and never freed, because the table is per-process and destroying it with one window would dangle every other window's descriptor. Landing 5 was marked for a subagent in the plan and **kept**: descriptor plumbing, coverage ordering and a shader are what CLAUDE.md §10 reserves, and a brief needs exact old→new text that a new design does not have. **GUI-verified**: an `ImageControl` draws the icon atlas as flat colour — the 3×3 grid of icon shapes with the MSDF's own per-channel colour fringing, cut by the texture's alpha; the `folder` cell renders as a clean amber silhouette through the MTSDF path; `accent` ramps left to right across a rounded box and `glow` renders as a radial ellipse with an alpha falloff, so both gradient kinds are exercised; and pointing `card.sampler` at the `close` cell collapsed the whole 360×220 quad, edge band included, to the glyph, with removing it restoring the box exactly — which is the only observation that separates "the branch works" from "the branch never runs". Row sizes read back at boot; no validation error beyond the pre-existing six barrier ones, the `DemoteToHelperInvocation` pair and the `SamplerAsset` default, and in particular none from the new binding. **Not exercised**: an image and a mask together (not expressible), a gradient on an image, a second window's copy of the gradient descriptor, and `edge` on a glyph.
